# cbox secrets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `cbox secret create | list | edit | delete` backed by the OS credential store, and `cbox up --secret NAME` resolving from it.

**Architecture:** A `secretstore` module holds the pure data rules (names, hosts, size), a `SecretStore` trait with a `keyring-core` implementation (macOS Keychain; a custom Credential Manager store on WSL), and a names-only index file. `commands/secret.rs` is the CLI. `up` turns a bare `--secret NAME` into a `SecretSpec` carrying a value read from the store, then goes through the unchanged `secrets::build`.

**Tech Stack:** Rust 2024, clap, `keyring-core` 1.0 + `apple-native-keyring-store`, `serde_json`, `rpassword` (hidden prompt).

**Spec:** `docs/design/secrets.md` (approved 2026-11-06). Read it first; it also holds the user's confirmed decisions.

## Global Constraints

- Never write a secret value to disk unencrypted, and never put one in argv or print it. No command prints a stored value.
- Each stored secret is one OS-store entry keyed `cbox/<name>` whose content is JSON `{"value","hosts","env"}`; `~/.config/cbox/secrets.json` holds only names.
- Names: lowercase letters, digits, `-`, `_`, starting with a letter; `gh` is reserved.
- `--host` is one comma-separated list: trim, drop empties and duplicates, never empty. `--env` is required on `create`.
- WSL entry limit is 2560 bytes of serialized JSON (bytes, not characters); check before writing and fail with a clear "too large" message.
- Linux with no store: error, no file fallback. A bare `--secret NAME` missing from the store fails `up`, never falls back to a host env var.
- `delete` asks for confirmation; `-y` skips it. `edit --host` replaces; `--add-host`/`--remove-host` adjust; `edit` never leaves zero hosts.
- The WSL PowerShell script is never written to disk: `powershell.exe -NoProfile -NonInteractive -EncodedCommand`, secret over stdin only.
- `--from-env` is out of scope. Commit and PR titles use Conventional Commits. Tests that touch env vars take `test_env_lock::lock()`.

## Review Focus

- Piped value ends in `\r\n` or `\n`: exactly one trailing newline is stripped; an empty result is rejected (Task 3).
- `create` on an existing name, including an orphan store entry with no index line: errors and says to run `delete` (Task 2).
- Index and store disagree (entry removed behind cbox's back): `list` shows "missing value", `delete` still succeeds (Task 2).
- A host env var or `-e` flag with the same name as a store secret's in-box env var: `up` fails and never puts the real value in the box (Task 4).
- Editing hosts/env without changing the value still triggers the resume warning; a flag-form secret's hash is unchanged (Task 4).
- Non-ASCII value near the WSL limit is measured in bytes (Task 1).
