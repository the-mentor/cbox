# cbox secrets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `cbox secret create | list | edit | delete` backed by the OS credential store, and `cbox up --secret NAME` resolving from it.

**Architecture:** A `secretstore` module holds the pure data rules (names, hosts, size), a `SecretStore` trait with a `keyring-core` implementation (macOS Keychain; a custom Credential Manager store on WSL), and a names-only index file. `commands/secret.rs` is the CLI. `up` turns a bare `--secret NAME` into a `SecretSpec` carrying a value read from the store, then goes through the unchanged `secrets::build`.

**Tech Stack:** Rust 2024, clap, `keyring-core` 1.0 + `apple-native-keyring-store` (feature `keychain`), `serde_json`, `rpassword` (hidden prompt).

**Spec:** `docs/design/secrets.md` (approved 2026-11-06). Read it first; it also holds the user's confirmed decisions.

> **Refreshed after execution.** This file now describes the code as built on PR #135 (branch `feat/secrets-store`, draft) and what is still open. Tasks 1-4 and 6 are done; Task 5 (WSL) is pending.

## Global Constraints

- Never write a secret value to disk unencrypted, and never put one in argv, an error message, a Debug print or a log. No command prints a stored value.
- Each stored secret is one OS-store entry (service `cbox`, account = the secret name) whose content is JSON `{"value","hosts","env"}`; `~/.config/cbox/secrets.json` (or `$XDG_CONFIG_HOME/cbox/secrets.json`) holds only names, mode 0600 in a 0700 dir.
- Names: lowercase letters, digits, `-`, `_`, starting with a letter; **`gh` and `gh_basic` are reserved**.
- `--host` is one comma-separated list: trim, drop empties and duplicates, never empty, **and no entry may contain `/` or whitespace** (a URL never matches the proxy). `--env` is required on `create`.
- WSL entry limit is 2560 bytes of serialized JSON (measured: 2560 saves, 2561 fails with "The stub received bad data"); check before writing and fail with a clear "too large" message.
- Linux with no store: error, no file fallback. A bare `--secret NAME` missing from the store fails `up`, never falls back to a host env var.
- `delete` asks for confirmation (`-y` skips), fails with `not found` for a name that exists nowhere, and works on a corrupt entry. `edit --host` replaces; `--add-host`/`--remove-host` adjust (add first, then remove); `edit` never leaves zero hosts; with any flag `edit` never reads a value; `edit` with no flags replaces the value; `edit` re-adds the name to a lost index.
- The WSL PowerShell script is never written to disk: `powershell.exe -NoProfile -NonInteractive -EncodedCommand`, secret over stdin only.
- `--from-env` is out of scope. Commit and PR titles use Conventional Commits. Tests that touch env vars or the process-global default keyring store take `test_env_lock::lock()`.

## As built (interfaces later work relies on)

- `secretstore/mod.rs`: `StoredSecret { value, hosts, env }` (redacting Debug), `validate_name`, `parse_hosts`, `validate_env`, `check_size(json, limit)`, `WSL_MAX_ENTRY_BYTES`, `to_json`, `from_json` (error carries line/column only).
- `secretstore/store.rs`: `trait SecretStore { label, max_entry_bytes, get -> Option<StoredSecret>, exists (does not parse), put, delete -> bool }`; `KeyringStore::new(label, limit)` over `keyring_core::Entry::new("cbox", name)`; `open_default()` (macOS registers the Keychain store; every other target returns "no secret store available on this platform ...").
- `secretstore/index.rs`: `Index { names }`, `load`, `save` (temp file removed then `create_new` 0600, rename), `insert`, `remove`.
- `secretstore/service.rs`: `check_absent`, `exists`, `create`, `list -> Vec<ListRow>`, `edit(store, index_path, name, EditChanges) -> EditOutcome`, `delete`; `HostChange { replace: Option<Vec>, add: Vec, remove: Vec }`.
- `commands/secret.rs`: `SecretCmd { Create, List, Edit, Delete }`, `read_value`, `prompt(label, name)` ("... (input is hidden, press Enter when done): "), `edit_changes`, `format_list`, `confirm_delete`.
- `secrets.rs`: `SecretSpec { name, env_var, hosts, value: Option, stored }` (redacting Debug), `is_store_reference`, `spec_from_store`, `check_unique_env` (rejects duplicate names and duplicate in-box env names across all specs), `resume_hashes(specs, built)`; `sidecar::hash_stored_secret(value, hosts, env)`.
- `up`: a bare `--secret NAME` opens the store lazily; the in-box env name is added to `source_vars`, so a same-named host variable or `-e` makes `up` fail closed.

## Review fixes already applied (so nobody redoes them)

macOS `keychain` feature (the build did not compile without it); delete of an unknown name; corrupt-entry errors name the secret and never echo content; `delete` and `create` handle a corrupt entry (probe without parsing, "already exists ... edit/delete" message); URL hosts rejected; resume-hash choice pinned by tests; HostChange collapsed to a struct; lost index repairable through `edit`; prompt says input is hidden; `gh_basic` reserved; docs aligned.

## Review Focus (what still deserves a test or a human)

- Real Keychain behavior on macOS: create/list/edit/delete round trip, access prompts, how a corrupt or non-UTF-8 entry is reported (PR description, steps 1-6).
- WSL: interop disabled, `powershell.exe` missing, PowerShell Constrained Language Mode (AppLocker/WDAC) breaking `Add-Type`, a 2561-byte entry, non-ASCII near the limit counted in bytes, `NoEntry` mapping from "Element not found".
- A `\r` in PowerShell error text when parsing stderr; exit code 1 on any uncaught exception.
- Very long pasted values on macOS (canonical-mode line limit, roughly 1024 chars): untested; the piped path is the workaround.
- Two `cbox secret` commands at the same instant can lose an index update (`Index::save` is load-modify-rename with a fixed temp name). Accepted for a one-person CLI.
